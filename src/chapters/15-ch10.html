Chapter 10

Subnetting

Subnetting-এর দুর্নাম আছে — CCNA-র পরীক্ষায় শত শত অঙ্ক কষতে হয় বলে। কিন্তু একজন developer-এর জন্য এটি আসলে একটি সরল প্রশ্নের উত্তর: "এই দুটি address কি একই network-এ?" এই একটি প্রশ্নের উত্তরের উপর নির্ভর করে packet সরাসরি যাবে নাকি router-এ যাবে।

10.1 Why does this exist?

আপনার machine প্রতিটি packet পাঠানোর আগে একটি সিদ্ধান্ত নেয়:

Destination কি আমার নিজের network-এ?
   হ্যাঁ →  ARP করে সরাসরি পাঠাব
   না   →  gateway-কে দিয়ে দেব

এই সিদ্ধান্ত নিতে হলে "আমার network" বলতে ঠিক কোন কোন address বোঝায় — তা সংজ্ঞায়িত করতে হবে। Subnet mask ঠিক সেই সীমারেখাটি আঁকে।

দ্বিতীয় কারণটি সাংগঠনিক। একটি প্রতিষ্ঠানের কাছে 10.0.0.0/8 আছে (১.৬ কোটি address)। সবাইকে একটি সমতল network-এ রাখলে broadcast storm হবে (Ch 6), নিরাপত্তার সীমানা টানা যাবে না, আর একটি ভুল সবাইকে প্রভাবিত করবে। তাই ভাগ করা হয়:

10.0.0.0/8  →  10.0.1.0/24   Engineering
               10.0.2.0/24   Sales
               10.0.3.0/24   Guest Wi-Fi
               10.0.10.0/24  Servers
               10.0.20.0/24  Database   ← এখানে firewall কড়া

10.2 Subnet Mask এবং CIDR

একটি subnet mask বলে দেয় IP address-এর কতগুলো bit "network" আর কতগুলো "host"।

দুটি লেখার রীতি, একই অর্থ:

  Dotted decimal :  255.255.255.0
  CIDR notation  :  /24

  255.255.255.0 = 11111111.11111111.11111111.00000000
                  └────── 24টি 1 ──────┘└─ 8টি 0 ─┘
                       network            host

নিয়ম: mask-এ 1 গুলো সবসময় বাঁ দিক থেকে একটানা।
      10101010 এরকম mask অবৈধ।

CIDR = Classless Inter-Domain Routing
"Classless" কারণ পুরনো class A/B/C ব্যবস্থা বাতিল —
এখন যেকোনো prefix length ব্যবহার করা যায়।
CIDRSubnet Maskমোট addressব্যবহারযোগ্য hostসাধারণ ব্যবহার
/8255.0.0.016,777,21616,777,214বিশাল private range
/16255.255.0.065,53665,534বড় প্রতিষ্ঠান, VPC
/24255.255.255.0256254সবচেয়ে প্রচলিত LAN
/25255.255.255.128128126ছোট বিভাগ
/26255.255.255.1926462ছোট office
/30255.255.255.25242দুই router-এর মাঝের link
/31255.255.255.25422*point-to-point (RFC 3021)
/32255.255.255.25511একক host-এর route
ℹ️ "−2" কেন

প্রতিটি subnet-এ দুটি address সংরক্ষিত:

  • Network address — সব host bit শূন্য (192.168.1.0)। এটি network-টিকে নির্দেশ করে, কোনো host নয়।
  • Broadcast address — সব host bit এক (192.168.1.255)। এখানে পাঠালে subnet-এর সবাই পায়।

/31 ব্যতিক্রম: দুটি router-এর মাঝের link-এ broadcast-এর প্রয়োজন নেই, তাই RFC 3021 দুটো address-ই host হিসেবে ব্যবহারের অনুমতি দেয়। /32 মানে একটি একক address — routing table বা firewall rule-এ ব্যবহৃত।

10.3 হাতে হিসাব — একটি /24

দেওয়া আছে:  192.168.1.0/24

/24 → প্রথম 24 bit স্থির, শেষ 8 bit পরিবর্তনশীল

  192  .  168  .   1   .    0
  স্থির    স্থির    স্থির    ← এই byte-টি 0 থেকে 255

Network address  : 192.168.1.0     (host bits সব 0)
প্রথম host        : 192.168.1.1
শেষ host          : 192.168.1.254
Broadcast         : 192.168.1.255   (host bits সব 1)

মোট address : 2⁸ = 256
Usable host : 256 − 2 = 254

10.4 হাতে হিসাব — একটি /26 (এখানেই আসল শেখা)

দেওয়া আছে:  192.168.1.0/26

/26 → শেষ byte-এর প্রথম 2 bit network, বাকি 6 bit host

শেষ byte:  n n h h h h h h
           └─┘ └────────┘
         network    host (2⁶ = 64টি address)

সুতরাং প্রতিটি subnet-এর আকার 64। চারটি subnet তৈরি হয়:

┌──────────────────┬─────────────┬────────────────┬─────────────┐
│ Subnet           │ Network     │ Host range     │ Broadcast   │
├──────────────────┼─────────────┼────────────────┼─────────────┤
│ 192.168.1.0/26   │ .0          │ .1   –  .62    │ .63         │
│ 192.168.1.64/26  │ .64         │ .65  –  .126   │ .127        │
│ 192.168.1.128/26 │ .128        │ .129 –  .190   │ .191        │
│ 192.168.1.192/26 │ .192        │ .193 –  .254   │ .255        │
└──────────────────┴─────────────┴────────────────┴─────────────┘

প্রতিটিতে usable host: 64 − 2 = 62
✓ দ্রুত হিসাবের কৌশল

মুখস্থ করার দরকার নেই, শুধু এই দুটি সূত্র:

Block size = 2^(32 − prefix)         ← মোট কত address
           = 256 − mask-এর শেষ octet  ← শেষ octet-এ কত

উদাহরণ /26:
  256 − 192 = 64   →  subnet গুলো শুরু হয় 0, 64, 128, 192-তে

উদাহরণ /28:
  mask = 255.255.255.240
  256 − 240 = 16   →  0, 16, 32, 48, 64, ... 240

এরপর: network address = আপনার IP-র নিচের নিকটতম গুণিতক; broadcast = পরের গুণিতক − 1।

10.6 "একই subnet-এ কিনা" — যেভাবে kernel হিসাব করে

Kernel-এর পদ্ধতিটি বাস্তবে খুবই সরল — একটি bitwise AND:

প্রশ্ন: আমি 192.168.1.5/24। আমি কি 192.168.1.200-এ
       সরাসরি পাঠাতে পারি?

ধাপ ১ — নিজের network বের করো:
   192.168.1.5    = 11000000.10101000.00000001.00000101
   mask /24       = 11111111.11111111.11111111.00000000
   AND            = 11000000.10101000.00000001.00000000
                  = 192.168.1.0

ধাপ ২ — গন্তব্যের network বের করো (একই mask দিয়ে):
   192.168.1.200  = 11000000.10101000.00000001.11001000
   mask /24       = 11111111.11111111.11111111.00000000
   AND            = 11000000.10101000.00000001.00000000
                  = 192.168.1.0

ধাপ ৩ — মিলল?  192.168.1.0 == 192.168.1.0  →  হ্যাঁ
       ⇒ একই subnet ⇒ ARP করে সরাসরি পাঠাও


এবার 192.168.2.50-এর জন্য:
   192.168.2.50 AND /24  =  192.168.2.0
   192.168.1.0 ≠ 192.168.2.0  →  না
   ⇒ ভিন্ন subnet ⇒ default gateway-কে দাও
🧠 Mental Model

Subnet mask কোনো "setting" নয় — এটি একটি প্রশ্নের উত্তর দেওয়ার যন্ত্র। প্রতিটি packet-এর জন্য kernel এই AND operation চালায় এবং সিদ্ধান্ত নেয়: local নাকি gateway। ভুল mask দিলে machine ভুল সিদ্ধান্ত নেয় — যেমন /24-এর বদলে /16 দিলে সে ভাববে 192.168.2.50-ও local, ARP করবে, কেউ উত্তর দেবে না, এবং connection timeout হবে। "একই তারে আছি কিন্তু ping যাচ্ছে না" — প্রায়ই এটিই কারণ।

10.7 Developer Perspective — কোথায় এটি লাগে

⚙️ বাস্তব ব্যবহার
  • Cloud VPC: AWS/GCP-তে VPC তৈরি করতে গেলেই CIDR চাইবে। 10.0.0.0/16 নিলে ভেতরে 10.0.1.0/24 (public subnet), 10.0.2.0/24 (private subnet) ইত্যাদি ভাগ করবেন। ভুল আকার বেছে নিলে পরে বদলানো কঠিন।
  • Security group / firewall rule: allow from 10.0.2.0/24 — অর্থাৎ শুধু ওই subnet-এর ২৫৪টি address থেকে। /32 মানে ঠিক একটি IP।
  • Kubernetes: pod CIDR, service CIDR, node CIDR — তিনটি আলাদা range, এবং এগুলো overlap করলে cluster ভেঙে পড়ে।
  • VPN ও peering: দুটি network যুক্ত করার সময় তাদের CIDR overlap করলে routing অসম্ভব। এজন্যই সবাই 192.168.1.0/24 ব্যবহার করার অভ্যাসটি সমস্যাজনক — দুটি অফিস যুক্ত করতে গেলেই সংঘাত।
  • Docker: 172.17.0.0/16 default। আপনার কোম্পানির network যদি ওই range ব্যবহার করে, Docker চালু করলেই কিছু internal service অদৃশ্য হয়ে যাবে।

10.8 কয়েকটি অনুশীলন

নিচেরগুলো নিজে করার চেষ্টা করুন, তারপর উত্তর খুলুন। Calculator ব্যবহার করে যাচাই করতে পারেন।

অনুশীলন ১ — 192.168.1.0/26 subnet-এ 192.168.1.70 কি আছে?

না। /26-এর block size 64, তাই subnet গুলো: 0–63, 64–127, 128–191, 192–255। 192.168.1.0/26-এর পরিধি .0 থেকে .63। .70 পড়ে পরের subnet-এ (192.168.1.64/26)। অর্থাৎ এই দুটি host সরাসরি কথা বলতে পারবে না — router লাগবে।

অনুশীলন ২ — 10.5.20.130/28: network address, broadcast, এবং host range কী?

/28 → block size = 2^(32−28) = 16। শেষ octet-এ 16-এর গুণিতক: 0, 16, 32, ... 128, 144, 160...
130 পড়ে 128 আর 143-এর মধ্যে। সুতরাং:

  • Network: 10.5.20.128
  • প্রথম host: 10.5.20.129
  • শেষ host: 10.5.20.142
  • Broadcast: 10.5.20.143
  • Usable: 14
অনুশীলন ৩ — একটি অফিসে ৫০০টি device। কোন prefix সবচেয়ে উপযুক্ত?

/23। হিসাব: /24 দেয় ২৫৪টি host — যথেষ্ট নয়। /23 দেয় 2⁹ − 2 = 510টি — ঠিক মানানসই। /22 দিত ১০২২টি — অপচয় (এবং broadcast domain অপ্রয়োজনীয়ভাবে বড়)।
তবে বাস্তবে অভিজ্ঞ network designer-রা এখানে দুটি /24 নিতেন এবং তাদের মাঝে router বসাতেন — যাতে broadcast domain ছোট থাকে এবং বিভাগ অনুযায়ী নিরাপত্তা-নীতি প্রয়োগ করা যায়।

অনুশীলন ৪ — আপনার machine 192.168.1.5/24। কেউ ভুল করে mask /16 করে দিল। কী ভাঙবে?

Machine এখন ভাববে পুরো 192.168.0.0 – 192.168.255.255 তার local network। ফলে 192.168.2.10-এ পাঠাতে গেলে সে gateway-কে না দিয়ে সরাসরি ARP করবে। কিন্তু ওই host অন্য physical segment-এ, তাই ARP-এর কোনো উত্তর আসবে না → packet কখনো পাঠানোই হবে না → timeout।
মজার ব্যাপার — Internet ঠিকই কাজ করবে (কারণ 8.8.8.8 এখনো non-local), কিন্তু পাশের subnet-এর কোনো server-এ পৌঁছানো যাবে না। এই অসামঞ্জস্যপূর্ণ উপসর্গটিই mask-এর ভুলের স্বাক্ষর।

🧪 Lab 10 — আপনার নিজের subnet

আমরা কী দেখতে চাইছি? — আপনার machine কোন subnet-এ আছে, সেখানে কতগুলো address সম্ভব, এবং সীমারেখাটি বাস্তবে কোথায়।

bash
# আপনার IP এবং prefix
ip -brief addr show           # যেমন: wlan0  UP  192.168.0.107/24

# আপনার routing table-এ subnet টি কীভাবে দেখাচ্ছে
ip route

# subnet-এর সব host scan করুন (ping sweep)
for i in $(seq 1 254); do (ping -c1 -W1 192.168.0.$i >/dev/null 2>&1 \
  && echo "192.168.0.$i সক্রিয়") & done; wait

যা লক্ষ্য করবেন: ip route-এ একটি লাইন থাকবে 192.168.0.0/24 dev wlan0 proto kernel scope link src 192.168.0.107 — লক্ষ্য করুন scope link, অর্থাৎ "এই গুলোতে সরাসরি পৌঁছানো যায়, gateway লাগবে না"। উপরের calculator-এ আপনার নিজের CIDR বসিয়ে দেখুন range মিলছে কিনা।

আমরা কী শিখলাম: Subnet কোনো তাত্ত্বিক ভাগ নয় — এটি routing table-এ একটি প্রকৃত entry, যা আপনার kernel প্রতিটি packet-এর জন্য পরীক্ষা করে। "Local" মানে ঠিক এই একটি লাইন।

📌 Chapter Summary
  • Subnet mask ঠিক করে address-এর কতগুলো bit network আর কতগুলো host।
  • CIDR (/24) এবং dotted mask (255.255.255.0) একই জিনিসের দুই লেখা।
  • Block size = 2^(32 − prefix) = 256 − mask-এর শেষ octet।
  • প্রতিটি subnet-এ ২টি address সংরক্ষিত: network (সব host bit 0) ও broadcast (সব host bit 1)।
  • Kernel bitwise AND দিয়ে ঠিক করে destination local কিনা — এটিই subnetting-এর মূল উদ্দেশ্য।
  • ভুল mask = ভুল local/remote সিদ্ধান্ত = রহস্যময় timeout।
  • বাস্তবে CIDR লাগে VPC design, firewall rule, Kubernetes, VPN ও Docker-এ।
✓ Quick Check
/24 এবং /25-এর পার্থক্য কী?

/24-এ ২৫৬টি address (২৫৪টি usable), /25-এ ১২৮টি (১২৬টি usable)। /25 একটি /24-কে দুই ভাগে ভাগ করে: x.x.x.0–127 এবং x.x.x.128–255। প্রতিটি ভাগ নিজস্ব network ও broadcast address সহ আলাদা subnet — অর্থাৎ তাদের মধ্যে কথা বলতে router লাগবে।

একটি subnet-এ দুটি address কেন ব্যবহার করা যায় না?

Network address (সব host bit 0) — এটি subnet-টিকে নির্দেশ করতে ব্যবহৃত হয় (routing table-এ, configuration-এ), কোনো নির্দিষ্ট host নয়। Broadcast address (সব host bit 1) — এখানে পাঠালে subnet-এর সবাই পায়, তাই এটি কোনো একক host-এর হতে পারে না। ব্যতিক্রম /31 (RFC 3021), যেখানে point-to-point link-এ broadcast অর্থহীন বলে দুটি address-ই ব্যবহারযোগ্য।

10.0.0.0/8 এবং 10.0.0.0/24 — একই network কি?

না। দুটোর network address একই (10.0.0.0), কিন্তু আকার সম্পূর্ণ ভিন্ন। /8-এ 10.0.0.0 থেকে 10.255.255.255 — ১.৬ কোটি address। /24-এ শুধু 10.0.0.0 থেকে 10.0.0.255 — ২৫৬টি। Prefix length ছাড়া একটি network address অসম্পূর্ণ তথ্য।

Kernel কীভাবে ঠিক করে একটি packet local নাকি remote?

Destination IP এবং নিজের IP — দুটোকেই subnet mask দিয়ে bitwise AND করে network portion বের করে। দুটি ফলাফল সমান হলে destination local (ARP করে সরাসরি পাঠাবে); অসমান হলে remote (default gateway-কে দেবে)। এটি প্রতিটি packet-এর জন্য routing table lookup-এর অংশ হিসেবে ঘটে।
