Essential Commands

bash
# ═══ Interface ও Address (L2/L3) ═══
ip link                          # interface up/down, MTU, MAC
ip -brief addr                   # সব IP, সংক্ষিপ্ত রূপে
ip neigh                         # ARP/neighbor table
ifconfig                         # macOS

# ═══ Routing (L3) ═══
ip route                         # routing table
ip route get 8.8.8.8             # ★ এই গন্তব্যে kernel কী করবে
netstat -rn                      # macOS

# ═══ পৌঁছানো যায় কি (L3) ═══
ping -c 4 host
ping -c 1 -M do -s 1472 host     # MTU পরীক্ষা (Linux)
traceroute -n host
mtr -r -c 50 host                # ★ loss কোথায় শুরু দেখায়

# ═══ Port ও Socket (L4) ═══
ss -tlnp                         # ★ কে কোন port-এ শুনছে
ss -tan state established        # সক্রিয় connection
ss -ti                           # ★ rtt, cwnd, retrans
ss -tan | awk 'NR>1{print $1}' | sort | uniq -c   # state গণনা
nc -zv host 443                  # port খোলা কি
lsof -i :8080                    # কোন process এই port-এ

# ═══ DNS ═══
dig example.com                  # সম্পূর্ণ
dig +short example.com           # শুধু উত্তর
dig +trace example.com           # ★ root থেকে পুরো পথ
dig @1.1.1.1 example.com         # নির্দিষ্ট resolver
dig -x 1.1.1.1                   # reverse
resolvectl flush-caches          # cache পরিষ্কার

# ═══ HTTP (L7) ═══
curl -v https://host             # সব header
curl -I https://host             # শুধু header
curl -w "%{http_code} %{time_total}s\n" -o /dev/null -s URL
curl --resolve host:443:1.2.3.4 https://host    # ★ DNS bypass

# ═══ TLS ═══
openssl s_client -connect host:443 -servername host </dev/null
openssl s_client -connect host:443 -showcerts </dev/null \
  | grep -E "^ *[0-9] s:|^ *i:"                 # chain দেখুন

# ═══ Packet Capture ═══
sudo tcpdump -i any -n port 443
sudo tcpdump -i any -n 'host X and not port 22'
sudo tcpdump -i any -n 'tcp[tcpflags] & tcp-rst != 0'   # কে RST দিচ্ছে
sudo tcpdump -i any -n -w cap.pcap 'port 443'  # ফাইলে

# ═══ Firewall ═══
sudo iptables -L -n -v
sudo ufw status verbose
sudo conntrack -L                # stateful table

Curl Timing — সবচেয়ে দরকারি এক-লাইনার

bash
curl -w "
DNS      : %{time_namelookup}s
TCP      : %{time_connect}s
TLS      : %{time_appconnect}s
পাঠানো   : %{time_pretransfer}s
প্রথম byte: %{time_starttransfer}s
মোট      : %{time_total}s
" -o /dev/null -s https://example.com

# ব্যাখ্যা:
#   TCP − DNS               = TCP handshake
#   TLS − TCP               = TLS handshake
#   starttransfer − pretransfer = ★ server-এর think time ★
#   total − starttransfer   = data transfer

Core Concepts — এক লাইনের mental model

Conceptএক লাইনে
MACInterface-এর hardware পরিচয়; এক hop-এর জন্য, প্রতিটি link-এ নতুন করে লেখা হয়
IPশ্রেণিবদ্ধ, routable ঠিকানা; end-to-end, পুরো যাত্রায় অপরিবর্তিত (NAT ছাড়া)
Subnet maskএকটি প্রশ্নের উত্তর দেওয়ার যন্ত্র: "এই destination কি local?"
ARPLocal network-এ IP → MAC; broadcast দিয়ে জিজ্ঞেস, router পেরোয় না
Default gateway"যা আমি চিনি না, তা যাকে দিই" — delegation
RoutingHop-by-hop; কেউ পুরো পথ জানে না, প্রত্যেকে next hop জানে; longest prefix জেতে
TTLHop counter; loop-এর বিরুদ্ধে নিরাপত্তা-বেষ্টনী; traceroute-এর ভিত্তি
ICMPNetwork-এর ত্রুটি ও নিয়ন্ত্রণ বার্তা; ping ও traceroute এর উপর দাঁড়িয়ে
Portএকটি host-এর ভেতরে process নির্বাচনের ১৬-bit সংখ্যা
SocketApplication ও kernel-এর সীমান্ত; একটি file descriptor
4-tupleএকটি connection-এর প্রকৃত পরিচয়: (srcIP, srcPort, dstIP, dstPort)
TCPঅবিশ্বস্ত packet-ব্যবস্থার উপর নির্ভরযোগ্য, ক্রমবদ্ধ byte stream — শুধু দুই প্রান্তে
UDPIP + port + checksum; বাকি সব আপনার দায়িত্ব
Flow controlReceiver-কে রক্ষা; স্পষ্ট সংকেত (rwnd)
Congestion controlNetwork-কে রক্ষা; অনুমাননির্ভর (loss/delay দেখে cwnd)
TIME_WAITশেষ ACK হারালে সামলানো + পুরনো packet নতুন connection-এ ঢুকতে না দেওয়া
DNSHierarchy + delegation + caching = বৈশ্বিক scale
TTL (DNS)একটি প্রতিশ্রুতি — পুরনো উত্তর ততক্ষণ ব্যবহৃত হতে পারে
HTTPStateless request/response; state client বহন করে (cookie/token)
TLSতিনটি একসাথে: confidentiality + integrity + authentication
CertificateCA-র স্বাক্ষরিত বিবৃতি: "এই public key এই domain-এর"
NATPort দিয়ে বহু private host একটি public IP-তে; state রাখতে বাধ্য
FirewallACCEPT / DROP (timeout) / REJECT (refused)
CDNদূরত্ব কমানো যায় না, তাই content কাছে আনা
Load balancerL4 = connection বণ্টন; L7 = প্রতিটি request
QUICUDP-র উপর TCP-র চেয়ে ভালো transport: stream-প্রতি reliability, 0-RTT, migration

দ্রুত হিসাব

Subnet:
  Block size   = 2^(32 − prefix) = 256 − mask-এর শেষ octet
  Usable hosts = 2^(32 − prefix) − 2
  /24 → 254   /25 → 126   /26 → 62   /27 → 30   /28 → 14

MTU/MSS:
  MSS = MTU − IP header − TCP header
      = 1500 − 20 − 20 = 1460   (IPv4)
      = 1500 − 40 − 20 = 1440   (IPv6)

Throughput:
  Throughput ≈ window / RTT
  BDP = bandwidth × RTT   ← পূর্ণ গতির জন্য প্রয়োজনীয় window
  Mbps ÷ 8 = MB/s

Loss-এর প্রভাব (Mathis):
  BW ≈ MSS / (RTT × √loss)
  0.1% loss @ 100ms RTT → ~12 Mbps সর্বোচ্চ

Latency-র উপাদান:
  propagation (দূরত্ব ÷ 200,000 km/s) — ভৌত সীমা
  + transmission (size ÷ bandwidth)
  + processing (μs)
  + queueing (0 – শত ms, সবচেয়ে পরিবর্তনশীল)

একটি HTTPS request-এর ন্যূনতম:
  DNS + TCP + TLS + HTTP = 4 RTT
