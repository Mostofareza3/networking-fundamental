Chapter 9

IP Addresses

127.0.0.1, 0.0.0.0, localhost, 192.168.1.5 — এই চারটি জিনিস প্রতিদিন ব্যবহার হয় এবং প্রায় সবাই অন্তত একটির অর্থ ভুল জানে। এই chapter সেই ভুলগুলো ঠিক করবে।

9.1 Why does this exist?

MAC address দিয়ে local delivery হয়ে গেল (Ch 6–8)। কিন্তু পৃথিবীর অন্য প্রান্তের একটি machine-এ পাঠাতে হলে? MAC address এখানে অকেজো — কারণ এতে কোনো কাঠামো নেই।

MAC ভিত্তিক global routing কল্পনা করুন:

  Router-এর table:
    AA:BB:CC:DD:EE:01 → port 3
    AA:BB:CC:DD:EE:02 → port 7
    AA:BB:CC:DD:EE:03 → port 1
    ... (পৃথিবীর প্রতিটি device-এর জন্য একটি করে line)
    ≈ 3,000,000,000+ entries

কোনো সংক্ষেপণ সম্ভব নয়, কারণ AA:BB:CC:DD:EE:01 এবং
AA:BB:CC:DD:EE:02 পাশাপাশি সংখ্যা হলেও তারা পৃথিবীর
দুই প্রান্তে থাকতে পারে। MAC-এ ভূগোলের কোনো তথ্য নেই।
💡 Why IP

IP address শ্রেণিবদ্ধ (hierarchical)। 203.0.113.0/24 — এই একটি entry দিয়ে ২৫৪টি host বোঝানো যায়। 10.0.0.0/8 দিয়ে ১ কোটি ৬০ লক্ষের বেশি। এই সংক্ষেপণকে বলে route aggregation, এবং এটিই Internet-এর routing table-কে ৯ লক্ষ entry-তে (২০২৬ সালের হিসাবে) ধরে রেখেছে — ৩০০ কোটির বদলে।

ডাক ব্যবস্থার সাথে তুলনা: ঢাকার সব চিঠি একসাথে ঢাকার দিকে পাঠানো যায় কারণ postcode-এ শ্রেণিবিন্যাস আছে। যদি প্রতিটি মানুষের একটি random নম্বর থাকত, ডাক ব্যবস্থা কাজ করত না।

9.2 IPv4-এর গঠন

একটি IPv4 address ৩২ bit। লেখা হয় চারটি dotted-decimal অংশে (প্রতিটি ০–২৫৫):

       192   .   168   .    1    .    5
        │         │         │         │
   11000000 . 10101000 . 00000001 . 00000101
   └───8 bit─┘ └─8 bit─┘ └─8 bit─┘ └─8 bit─┘
   
   মোট 32 bit  →  2³² = 4,294,967,296 সম্ভাব্য address

   কিন্তু বাস্তবে ব্যবহারযোগ্য অনেক কম, কারণ বিরাট অংশ
   সংরক্ষিত (private, multicast, loopback, reserved)।
   এবং ২০১১ সালেই IANA-র pool শেষ হয়ে গেছে।
ℹ️ IPv4 কেন ফুরিয়ে গেল

৪৩০ কোটি সংখ্যাটি ১৯৮১ সালে অসীম মনে হয়েছিল — তখন Internet-এ কয়েকশ computer। আজ প্রতিটি মানুষের হাতে ফোন, laptop, smartwatch, TV, IoT device। ২০১১ সালে IANA-র শেষ block বণ্টিত হয়। দুটি সমাধান এসেছে: NAT (একটি public IP-র পেছনে হাজারো device, Ch 34) এবং IPv6 (১২৮ bit)।

9.3 IP address কী identify করে

⚠️ একটি সূক্ষ্ম কিন্তু গুরুত্বপূর্ণ পার্থক্য

IP address একটি computer-কে identify করে না। এটি identify করে একটি network interface-কে — আরও নির্দিষ্ট করে বললে, "একটি নির্দিষ্ট network-এ একটি নির্দিষ্ট সংযোগ-বিন্দু"।

ফলাফল:

  • একটি machine-এর একাধিক IP থাকতে পারে (Ethernet, Wi-Fi, VPN, Docker — প্রতিটির আলাদা)।
  • একটি router-এর প্রতিটি interface-এ আলাদা IP — এটি router-এর সংজ্ঞারই অংশ।
  • আপনি ভিন্ন Wi-Fi-তে গেলে আপনার IP বদলে যায়, কারণ আপনি ভিন্ন network-এ যুক্ত হয়েছেন।
  • এজন্যই mobile device-এ TCP connection ভেঙে যায় Wi-Fi থেকে cellular-এ গেলে — IP বদলে গেছে, তাই connection-এর পরিচয়ই বদলে গেছে (Ch 45-এ QUIC কীভাবে এটি সমাধান করে দেখব)।

9.4 Network Portion এবং Host Portion

প্রতিটি IP address দুটি অংশে ভাগ:

          192.168.1.5 / 24
          └────────┘ └┘  └┘
           NETWORK  HOST  prefix length

  /24 মানে: প্রথম 24 bit = network, বাকি 8 bit = host

  11000000.10101000.00000001 . 00000101
  └──────── network ────────┘  └─ host ─┘
         192.168.1                 .5

  একই network-এর সবাই:  192.168.1.___
  ভিন্ন network:         192.168.2.___  ← ভিন্ন, router লাগবে
🧠 Mental Model — দুই স্তরের ঠিকানা

IP address = [কোন এলাকা] + [সেই এলাকার কোন বাড়ি]। Router-রা শুধু "কোন এলাকা" অংশটি দেখে সিদ্ধান্ত নেয় — বাড়ির নম্বর নিয়ে তাদের মাথাব্যথা নেই। শুধু শেষ router, যে ওই এলাকার ভেতরে আছে, সে বাড়ির নম্বর দেখে (এবং ARP করে MAC বের করে)।

এই দুই-স্তরের ব্যবস্থাই Internet-কে scalable করেছে। বিস্তারিত পরের chapter-এ।

9.5 বিশেষ address গুলো — যেগুলো নিয়ে সবচেয়ে বেশি বিভ্রান্তি

Addressনামপ্রকৃত অর্থ
127.0.0.1Loopback"এই machine নিজে"। Traffic কখনো NIC পর্যন্ত পৌঁছায় না — kernel-এর ভেতরেই ঘুরে আসে। পুরো 127.0.0.0/8 block-ই loopback (127.5.9.2-ও কাজ করে)।
localhostHostnameএকটি নাম, address নয়। /etc/hosts ফাইলে এটি 127.0.0.1 এবং ::1-এ mapped। এটি বদলানো যায়।
0.0.0.0Unspecified / Wildcardপ্রসঙ্গভেদে দুই অর্থ। bind()-এ: "এই machine-এর সব interface-এ শোনো"। Routing table-এ: "যেকোনো গন্তব্য" (default route)। এটি কখনো কোনো packet-এর গন্তব্য হয় না।
192.168.0.0/16Private (RFC 1918)ঘর ও ছোট অফিসের জন্য। Internet-এ routable নয়।
10.0.0.0/8Private (RFC 1918)বড় প্রতিষ্ঠান ও cloud VPC-তে সবচেয়ে প্রচলিত। ১.৬ কোটি address।
172.16.0.0/12Private (RFC 1918)Docker-এর default bridge এখান থেকে নেয়।
169.254.0.0/16Link-local (APIPA)DHCP ব্যর্থ হলে machine নিজে নিজে এটি বেছে নেয়। এই IP দেখলেই বুঝবেন DHCP কাজ করেনি।
255.255.255.255Limited broadcast"এই segment-এর সবাই"। DHCP Discover এটি ব্যবহার করে (তখনো নিজের IP নেই বলে)।
::1IPv6 loopbackIPv6-এর 127.0.0.1।

9.6 0.0.0.0 বনাম 127.0.0.1 — সবচেয়ে বেশি জিজ্ঞাসিত প্রশ্ন

আপনি Node.js-এ server চালালেন এবং ফোন থেকে সেটি খুলতে পারছেন না। কারণ প্রায় নিশ্চিতভাবে এটি:

app.listen(3000, "127.0.0.1")     app.listen(3000, "0.0.0.0")
                                   
Kernel বলে:                        Kernel বলে:
"শুধু loopback interface-এ         "সব interface-এ শোনো:
 শোনো"                              lo, eth0, wlan0, docker0..."

┌─────────────────────┐            ┌─────────────────────┐
│  Machine            │            │  Machine            │
│                     │            │                     │
│  lo    (127.0.0.1) ✓│  শুনছে      │  lo    (127.0.0.1) ✓│

⚙️ Developer Perspective

এটি নিছক তথ্য নয়, একটি নিরাপত্তা-সিদ্ধান্ত। 127.0.0.1-এ bind করা মানে "এই service শুধু এই machine-এর ভেতরে ব্যবহার্য" — একটি database বা internal admin panel-এর জন্য এটিই সঠিক। 0.0.0.0-তে bind করা মানে "যে কেউ, যেকোনো interface থেকে আসতে পারে" — যা firewall না থাকলে বিপজ্জনক।

Docker container-এ এটি আরও জরুরি: container-এর ভেতরে 127.0.0.1-এ bind করলে -p 3000:3000 দিয়েও বাইরে থেকে পৌঁছানো যাবে না, কারণ Docker-এর port forwarding container-এর bridge interface-এ আসে, loopback-এ নয়। Container-এর ভেতরে প্রায় সবসময় 0.0.0.0-তে bind করতে হয়।

9.7 IPv6 সংক্ষেপে

IPv6 ১২৮ bit — সংখ্যাটি ৩.৪ × ১০³⁸, অর্থাৎ পৃথিবীর প্রতিটি বালুকণার জন্য কোটি কোটি address।

পূর্ণ রূপ:
2001:0db8:0000:0000:0000:ff00:0042:8329

সংক্ষেপের দুটি নিয়ম:
1. প্রতিটি group-এর শুরুর শূন্য বাদ:
   2001:db8:0:0:0:ff00:42:8329
2. পরপর শূন্য group গুলো "::" দিয়ে (শুধু একবার):
   2001:db8::ff00:42:8329

উদাহরণ:
  ::1                    → loopback (127.0.0.1-এর সমতুল্য)
  ::                     → unspecified (0.0.0.0-এর সমতুল্য)
  fe80::/10              → link-local (প্রতিটি interface-এ থাকে)
  2000::/3               → global unicast (প্রকৃত public address)

URL-এ লিখতে হয় bracket দিয়ে, port-এর সাথে বিভ্রান্তি এড়াতে:
  http://[2001:db8::1]:8080/api

9.8 Common Confusions

MYTH

একটি IP address একটি application বা service-কে identify করে।

REALITY

IP address identify করে একটি network interface-কে (network layer-এ একটি সংযোগ-বিন্দু)। কোন application পাবে সেটি ঠিক করে port number (transport layer, Ch 15)। একটি server-এ ৫০টি service চলতে পারে একই IP-তে — আলাদা করে শুধু port। তাই একটি service-কে সম্পূর্ণভাবে চিহ্নিত করতে লাগে protocol + IP + port।

MYTH

localhost এবং 127.0.0.1 ঠিক একই জিনিস।

REALITY

localhost একটি নাম যা resolve করতে হয়; 127.0.0.1 একটি address। বাস্তব পার্থক্য আছে: (১) আধুনিক system-এ localhost প্রায়ই আগে ::1 (IPv6)-এ resolve হয় — তাই আপনার server যদি শুধু IPv4-এ শুনছে, localhost ব্যর্থ হতে পারে অথচ 127.0.0.1 কাজ করবে (Node.js-এ এটি বহুল পরিচিত সমস্যা)। (২) /etc/hosts বদলে localhost-কে অন্য কিছুতে দেখানো যায়। (৩) Name resolution-এ সামান্য বাড়তি খরচ।

MYTH

Private IP address গুলো "কম নিরাপদ" বা "নকল"।

REALITY

Private address সম্পূর্ণ বৈধ ও কার্যকর address — শুধু এগুলো Internet-এ globally routable নয়। প্রতিটি ঘরে আলাদা "১ নম্বর ঘর" থাকার মতো — ভবনের ভেতরে অর্থপূর্ণ, বাইরে অর্থহীন। এগুলো NAT-এর মাধ্যমে বাইরে যায় (Ch 34)। প্রকৃতপক্ষে বিশ্বের বেশিরভাগ device-ই private address ব্যবহার করে।

🧪 Lab 9 — আপনার সব IP address এবং তাদের অর্থ

আমরা কী দেখতে চাইছি? — এই chapter-এর প্রতিটি ধরনের address (loopback, private, link-local) আপনার নিজের machine-এ শনাক্ত করা এবং bind-এর পার্থক্যটি হাতে-কলমে পরীক্ষা।

bash
# সব interface এবং তাদের address
ip -brief addr        # Linux — সংক্ষিপ্ত ও পরিষ্কার
ifconfig              # macOS

# আপনার public IP (যেটি বাইরের দুনিয়া দেখে)
curl -s ifconfig.me; echo

# পরীক্ষা: দুটি ভিন্ন bind
python3 -m http.server 8000 --bind 127.0.0.1 &
curl -s -o /dev/null -w "loopback থেকে: %{http_code}\n" http://127.0.0.1:8000
curl -s -o /dev/null -w "নিজের LAN IP থেকে: %{http_code}\n" http://$(hostname -I | awk '{print $1}'):8000
kill %1

যা লক্ষ্য করবেন: প্রথম curl সফল (200), দ্বিতীয়টি ব্যর্থ (000 / connection refused) — যদিও দুটোই একই machine! কারণ server শুধু loopback interface-এ শুনছে। --bind 0.0.0.0 দিয়ে আবার চালান — এবার দুটোই সফল। এছাড়া লক্ষ্য করুন curl ifconfig.me-এর public IP আপনার local IP থেকে সম্পূর্ণ আলাদা — এটিই NAT (Ch 34)।

আমরা কী শিখলাম: "Server চলছে" যথেষ্ট নয় — কোন interface-এ শুনছে সেটাই নির্ধারণ করে কে পৌঁছাতে পারবে। আর আপনার machine-এর "IP address" বলে একক কিছু নেই; আছে interface-প্রতি address, এবং বাইরের দুনিয়া আপনাকে সম্পূর্ণ ভিন্ন একটি address-এ দেখে।

📌 Chapter Summary
  • IP address শ্রেণিবদ্ধ (network + host) — এই কাঠামোই route aggregation ও global routing সম্ভব করেছে।
  • IP address interface-কে চিহ্নিত করে, machine বা application-কে নয়।
  • 127.0.0.1 = নিজের machine (kernel-এর ভেতরেই থাকে); localhost = একটি নাম যা এতে resolve হয় (বা ::1-এ)।
  • 0.0.0.0 bind-এ মানে "সব interface", routing table-এ মানে "যেকোনো গন্তব্য"।
  • Private range: 10/8, 172.16/12, 192.168/16 — বৈধ কিন্তু Internet-এ routable নয়।
  • 169.254.x.x দেখলেই বুঝবেন DHCP ব্যর্থ হয়েছে।
  • IPv6 ১২৮ bit, broadcast নেই, NAT অপ্রয়োজনীয়, ARP-এর বদলে NDP।
✓ Quick Check
একটি machine-এ কি একাধিক IP address থাকতে পারে? কেন?

হ্যাঁ, এবং এটিই স্বাভাবিক। IP address interface-এর সাথে যুক্ত, machine-এর সাথে নয়। একটি সাধারণ dev machine-এ থাকে: 127.0.0.1 (lo), একটি LAN IP (wlan0/eth0), একটি Docker bridge IP (docker0), VPN চালু থাকলে আরেকটি। একটি interface-এ একাধিক IP-ও দেওয়া যায় (IP aliasing)।

আপনার dev server localhost:3000-এ কাজ করে কিন্তু ফোন থেকে 192.168.1.5:3000 খোলে না। কারণ কী?

প্রায় নিশ্চিতভাবে server 127.0.0.1-এ bind করা, 0.0.0.0-তে নয়। Kernel শুধু loopback interface-এ ওই port-এ শুনছে; Wi-Fi interface-এ আসা packet-এর জন্য কোনো listener নেই, তাই kernel TCP RST পাঠায় → "connection refused"। সমাধান: 0.0.0.0-তে bind করুন (এবং firewall-এ port খোলা আছে কিনা দেখুন)।

169.254.10.23 IP দেখলে আপনি কী সিদ্ধান্তে আসবেন?

DHCP ব্যর্থ হয়েছে। Machine কোনো DHCP server থেকে উত্তর পায়নি, তাই APIPA/link-local নিয়ম মেনে নিজেই 169.254.0.0/16 থেকে একটি address বেছে নিয়েছে। এই address দিয়ে একই segment-এর অন্যদের সাথে কথা বলা যায়, কিন্তু কোনো gateway নেই — তাই Internet-এ পৌঁছানো যাবে না। সন্দেহের তালিকা: তার/Wi-Fi সংযোগ, DHCP server বন্ধ, VLAN ভুল।

MAC address থাকতেও IP address কেন দরকার — এক বাক্যে?

কারণ MAC সমতল ও অসংক্ষেপণযোগ্য, ফলে global routing table কয়েকশ কোটি entry-র হতো; IP-তে network prefix থাকায় লক্ষ লক্ষ host-কে একটি route entry-তে সংক্ষেপ করা যায়।

Wi-Fi থেকে mobile data-তে গেলে চলমান download কেন ভেঙে যায়?

কারণ আপনার IP address বদলে গেছে। একটি TCP connection চিহ্নিত হয় চারটি জিনিস দিয়ে: source IP, source port, destination IP, destination port। source IP বদলে গেলে সেটি আর একই connection নয় — server-এর কাছে পুরনো connection মৃত। (Ch 45-এ দেখব QUIC এটি সমাধান করে connection ID ব্যবহার করে, IP-এর বদলে।)
