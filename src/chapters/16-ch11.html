Chapter 11

Default Gateway

আপনার machine পৃথিবীর প্রতিটি network-এর পথ জানে না — এবং জানার দরকারও নেই। তার শুধু একটি জিনিস জানা দরকার: "যা আমি চিনি না, তা কার কাছে দেব।"

11.1 Why does this exist?

আপনার laptop 142.250.190.14 (google.com)-এ packet পাঠাতে চায়। এটি local নয়। এখন কী?

একটি বিকল্প হতো — laptop-এ পৃথিবীর সব network-এর route রাখা। সমস্যা: বর্তমানে global routing table-এ প্রায় ৯ লক্ষ prefix, যা প্রতি সেকেন্ডে বদলাচ্ছে। প্রতিটি laptop, ফোন, IoT bulb-কে এই table রাখতে ও update করতে হলে ব্যবস্থাটি অচল হয়ে যেত।

💡 Why Default Gateway

সমাধান: "আমি জানি না, কিন্তু আমি এমন একজনকে চিনি যে জানে।" আপনার machine শুধু দুটি জিনিস জানে — (১) তার নিজের subnet-এ কারা আছে, আর (২) বাকি সব কিছুর জন্য একটি ঠিকানা: default gateway। এটি computer science-এর একটি পরিচিত নকশা: delegation — নিজে না পারলে যে পারে তার কাছে পাঠাও।

এবং এই নকশাটি recursive: আপনার router-ও সব জানে না, সে তার ISP-কে দেয়। ISP-ও সব জানে না, সে তার upstream-কে দেয়। শেষ পর্যন্ত Internet-এর core-এ কিছু router আছে যারা প্রকৃতপক্ষে পুরো table রাখে (Ch 42)।

🧠 Mental Model — বইয়ের কেন্দ্রীয় ধারণা

Destination IP = চূড়ান্ত গন্তব্য (কখনো বদলায় না)।
Destination MAC = পরের hop (প্রতি hop-এ বদলায়)।

এই দুই লাইনই routing-এর পুরো ভিত্তি। আপনার machine Google-এর server-এর MAC কোনোদিন জানে না — সে শুধু নিজের router-এর MAC জানে। Router-ও Google-এর MAC জানে না — সে পরের router-এর MAC জানে। এভাবে চেইন চলতে থাকে, আর IP address পুরো পথ জুড়ে একই থাকে, শেষ গন্তব্যকে নির্দেশ করে।

11.3 একটি বাস্তব routing table পড়া

bash
$ ip route
default via 192.168.0.1 dev wlan0 proto dhcp metric 600
169.254.0.0/16 dev wlan0 scope link metric 1000
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1
192.168.0.0/24 dev wlan0 proto kernel scope link src 192.168.0.107

লাইন ধরে ধরে পড়া যাক:

Routeঅর্থ
default via 192.168.0.1 dev wlan0"যা অন্য কোনো নিয়মে পড়ে না, তা wlan0 দিয়ে 192.168.0.1-কে পাঠাও।" default = 0.0.0.0/0 = সব কিছু।
192.168.0.0/24 ... scope link"এই ২৫৪টি address সরাসরি পৌঁছানো যায় — কোনো via নেই, তাই gateway লাগবে না, ARP করেই পাঠাও।"
172.17.0.0/16 dev docker0Docker-এর তৈরি করা route। Container-দের সাথে কথা বলার জন্য।
169.254.0.0/16Link-local route, স্বয়ংক্রিয়ভাবে যোগ হয়।
metric 600একাধিক route মিললে কম metric-এর টি জেতে। Wi-Fi ও Ethernet দুটোই সংযুক্ত থাকলে এটিই ঠিক করে কোনটি ব্যবহার হবে।
✓ via থাকা মানে কী

via আছে = "এটি অন্য কারো হাতে দিতে হবে" (indirect / next-hop route)।
via নেই, শুধু scope link = "এটি সরাসরি আমার নাগালে" (directly connected route)।
Routing table পড়ার সময় প্রথমেই এই পার্থক্যটি দেখুন — এতেই বোঝা যায় packet সরাসরি যাবে নাকি gateway পেরোবে।

11.4 Gateway যখন থাকে না

এই তিনটি পরিস্থিতির উপসর্গ ভিন্ন এবং সেগুলো চিনতে পারা debugging-এর জন্য মূল্যবান:

পরিস্থিতিউপসর্গযাচাই
কোনো default route নেইLocal IP-তে ping যায়, বাইরে Network is unreachable — তাৎক্ষণিক error, timeout নয়ip route | grep default — খালি?
Gateway সেট আছে কিন্তু অকার্যকরGateway-তেই ping যায় না। সব কিছু timeout।ping <gateway-IP>
Gateway কাজ করে, কিন্তু upstream ভাঙাGateway-তে ping যায়, তার পরে সব timeouttraceroute 1.1.1.1 — কোথায় থামছে দেখুন
⚙️ Developer Perspective — error message পড়া

Network is unreachable এবং Connection timed out — এই দুটি সম্পূর্ণ ভিন্ন জিনিস, এবং পার্থক্যটি জানা সময় বাঁচায়:

  • Network unreachable = আপনার নিজের kernel বলছে "আমি জানিই না কোথায় পাঠাব"। Packet কখনো তারেই ওঠেনি। সমস্যা আপনার machine-এ — routing table-এ।
  • Timed out = packet পাঠানো হয়েছে, কিন্তু কোনো উত্তর আসেনি। সমস্যা কোথাও পথে, বা গন্তব্যে, বা firewall-এ।
  • Connection refused = packet পৌঁছেছে এবং গন্তব্য সক্রিয়ভাবে TCP RST দিয়ে না বলেছে। অর্থাৎ routing পুরোপুরি ঠিক আছে — শুধু ওই port-এ কেউ শুনছে না। এটি আসলে একটি ভালো খবর।

11.5 একাধিক gateway এবং route-এর অগ্রাধিকার

আপনার machine-এ একই সাথে Wi-Fi, Ethernet এবং VPN থাকতে পারে — প্রতিটির নিজস্ব gateway। কে জেতে?

$ ip route
default via 10.8.0.1   dev tun0   metric 50    ← VPN
default via 192.168.0.1 dev wlan0 metric 600   ← Wi-Fi
default via 192.168.1.1 dev eth0  metric 100   ← Ethernet

নিয়ম: সবচেয়ে নির্দিষ্ট route আগে (longest prefix match, Ch 12)।
      সমান নির্দিষ্টতা হলে সবচেয়ে কম metric জেতে।

এখানে সব default (/0) — তাই metric 50 জেতে → VPN দিয়ে যাবে।

এজন্যই "full tunnel" VPN চালু করলে সব traffic VPN-এ যায়:
সে একটি কম-metric-এর default route বসিয়ে দেয়।

"Split tunnel" VPN default route বদলায় না; শুধু নির্দিষ্ট
prefix-এর জন্য route যোগ করে, যেমন:
    10.0.0.0/8 via 10.8.0.1 dev tun0
যেহেতু /8 > /0 (বেশি নির্দিষ্ট), শুধু ওই traffic VPN-এ যায়।
🧪 Lab 11 — Gateway-এর পথ অনুসরণ করুন

আমরা কী দেখতে চাইছি? — আপনার packet প্রথমে ঠিক কোন যন্ত্রটির কাছে যাচ্ছে, এবং local বনাম remote গন্তব্যের সিদ্ধান্তটি বাস্তবে কীভাবে ঘটছে।

bash
# default route কী?
ip route show default

# একটি নির্দিষ্ট গন্তব্যের জন্য kernel কোন route বেছে নেবে —
# সরাসরি জিজ্ঞেস করুন (packet না পাঠিয়েই):
ip route get 1.1.1.1
ip route get 192.168.0.50        # আপনার নিজের subnet-এর কিছু

# প্রথম hop টি কে, বাস্তবে দেখুন
traceroute -m 3 1.1.1.1          # প্রথম লাইনটিই আপনার gateway

যা লক্ষ্য করবেন: ip route get 1.1.1.1 দেখাবে 1.1.1.1 via 192.168.0.1 dev wlan0 src 192.168.0.107 — লক্ষ্য করুন via, অর্থাৎ gateway লাগবে। কিন্তু ip route get 192.168.0.50-এ কোনো via থাকবে না — শুধু dev wlan0, কারণ এটি সরাসরি পৌঁছানো যায়। traceroute-এর প্রথম লাইনটি ঠিক সেই gateway IP-ই দেখাবে।

আমরা কী শিখলাম: ip route get হলো kernel-এর সিদ্ধান্ত-প্রক্রিয়ায় সরাসরি প্রশ্ন করার উপায় — কোনো packet না পাঠিয়েই আপনি জেনে নিতে পারেন সে কী করত। Debugging-এ এটি অত্যন্ত কার্যকর, কারণ এটি "কী হওয়ার কথা" নয়, "কী হবে" বলে দেয়।

📌 Chapter Summary
  • Default gateway = "যা আমি চিনি না তা যাকে দেব" — delegation-এর নীতি।
  • প্রতিটি packet-এর জন্য kernel প্রশ্ন করে: destination কি আমার subnet-এ? হ্যাঁ → সরাসরি; না → gateway।
  • via সহ route = indirect (gateway লাগবে); scope link = directly connected।
  • Destination IP কখনো বদলায় না; destination MAC প্রতি hop-এ বদলায়।
  • Network unreachable (আমার routing table-এর সমস্যা) ≠ timeout (পথে সমস্যা) ≠ connection refused (পৌঁছেছে, listener নেই)।
  • একাধিক default route থাকলে সবচেয়ে কম metric জেতে — VPN এভাবেই traffic দখল করে।
✓ Quick Check
Destination local না হলে আপনার machine কার MAC address খোঁজে?

Default gateway-এর MAC। গন্তব্যের MAC কখনোই নয় — সেটি অন্য network-এ, আর ARP broadcast router পেরোয় না। Frame-এর destination MAC হয় gateway-এর, কিন্তু IP header-এর destination IP থাকে আসল চূড়ান্ত গন্তব্যের।

Network is unreachable এবং Connection timed out-এর মধ্যে কোনটি বেশি "স্থানীয়" সমস্যা?

Network is unreachable — এটি আপনার নিজের kernel তৈরি করেছে, packet তারেই ওঠেনি। কারণ routing table-এ ওই গন্তব্যের জন্য কোনো মিল নেই (সাধারণত default route অনুপস্থিত)। Timed out মানে packet বেরিয়ে গেছে কিন্তু উত্তর আসেনি — সমস্যা পথে, গন্তব্যে বা firewall-এ।

VPN চালু করলে হঠাৎ সব traffic কেন VPN দিয়ে যায়?

Full-tunnel VPN একটি নতুন default route (0.0.0.0/0) যোগ করে VPN interface-এর দিকে, এবং সেটির metric রাখে বিদ্যমান default route-এর চেয়ে কম। যেহেতু দুটোই সমান নির্দিষ্ট (/0), tie-break হয় metric দিয়ে — VPN জেতে। Split-tunnel VPN default route ছোঁয় না, শুধু নির্দিষ্ট prefix (যেমন 10.0.0.0/8) যোগ করে, যা longest-prefix-match-এ জিতে শুধু সেই traffic-কে টেনে নেয়।

আপনার router-ও কি পৃথিবীর সব route জানে?

না। বাসার router-ও প্রায় কিছুই জানে না — তার একটি default route আছে ISP-এর দিকে। ISP-এর router বেশি জানে কিন্তু সবটা নয়, সে তার upstream-কে দেয়। শুধু Internet-এর core-এর default-free zone-এর router-রা পুরো global table (~৯ লক্ষ prefix) রাখে এবং তাদের কোনো default route থাকে না। এটি একটি recursive delegation কাঠামো (Ch 42)।
