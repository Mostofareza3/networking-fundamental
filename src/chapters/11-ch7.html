Chapter 7

Switches

Switch-এর কেউ configuration করে না, তবু সে ঠিক জানে কোন machine কোন port-এ আছে। কীভাবে? উত্তরটি সুন্দর রকমের সরল — সে কখনো জিজ্ঞেস করে না, শুধু শোনে।

7.1 Why does this exist?

Switch-এর পূর্বসূরি ছিল hub। Hub-এর যুক্তি ছিল বোকার মতো সরল: এক port-এ যা আসে, বাকি সব port-এ পাঠিয়ে দাও।

HUB (পুরনো, বোকা)                SWITCH (আধুনিক, শেখে)

PC1 ──▶ Hub                       PC1 ──▶ Switch
         ├──▶ PC2  (চেয়েছিল)               └──▶ PC2 ✓
         ├──▶ PC3  (চায়নি, তবু পেল)
         └──▶ PC4  (চায়নি, তবু পেল)        PC3, PC4 কিছুই পায় না

সমস্যা:                            সুবিধা:
• সবাই সবার data দেখে              • গোপনীয়তা
• Bandwidth ভাগাভাগি               • প্রতিটি port-এ পূর্ণ bandwidth
• Collision হয়                     • Collision নেই (full duplex)
• অপ্রয়োজনীয় CPU খরচ               • CPU বাঁচে
💡 Why

Switch একটি সমস্যা সমাধান করে: একটি shared medium-এ কীভাবে data শুধু তার প্রাপকের কাছে পাঠানো যায়, কোনো মানুষের configuration ছাড়াই? সমাধানটি হলো — traffic দেখে নিজে নিজে শেখা। এটি networking-এর অন্যতম মার্জিত design, এবং এটি সম্পূর্ণ স্বয়ংক্রিয়।

7.2 MAC Address Table

প্রতিটি switch একটি table রাখে — MAC address table (একে CAM table বা forwarding table-ও বলা হয়)। এটি খুবই সরল:

┌───────────────────┬──────┬────────────┐
│ MAC Address       │ Port │ Age (sec)  │
├───────────────────┼──────┼────────────┤
│ AA:AA:AA:AA:AA:AA │  1   │     12     │
│ BB:BB:BB:BB:BB:BB │  2   │      5     │
│ CC:CC:CC:CC:CC:CC │  3   │    248     │
└───────────────────┴──────┴────────────┘

Age খুব গুরুত্বপূর্ণ — সাধারণত 300 সেকেন্ড পরে entry মুছে যায়।
কেন? কারণ কেউ laptop-টি অন্য port-এ লাগাতে পারে।
Table চিরস্থায়ী হলে সেই laptop আর কখনো traffic পেত না।

7.3 তিনটি কাজ — Learning, Forwarding, Flooding

Learning — Source MAC দেখে

Switch যখনই কোনো port-এ একটি frame পায়, সে frame-এর source MAC এবং সেই port নম্বর table-এ লিখে রাখে।

🧠 এখানেই আসল চালাকি

Switch destination দেখে forward করে, কিন্তু source দেখে শেখে। যুক্তিটি নিখুঁত: "port 3-এ যদি AA:AA থেকে একটি frame এল, তার মানে AA:AA অবশ্যই port 3-এর দিকে আছে।" কোনো protocol নেই, কোনো ঘোষণা নেই, কোনো configuration নেই — শুধু নীরব পর্যবেক্ষণ।

Forwarding — জানা থাকলে

Destination MAC table-এ থাকলে সেই একটি port-এ পাঠাও। ব্যস।

Flooding — না জানা থাকলে

Destination MAC table-এ না থাকলে (বা broadcast হলে) — যে port দিয়ে এসেছে সেটি বাদে বাকি সব port-এ পাঠাও। এটি hub-এর আচরণ, কিন্তু switch এটি করে শুধু প্রথমবার। উত্তর এলেই সে শিখে ফেলে।

7.4 ধাপে ধাপে — একটি switch যেভাবে শেখে

একটি একদম নতুন switch, table সম্পূর্ণ খালি। PC1 (AA:AA, port 1) → PC2 (BB:BB, port 2)-কে পাঠাতে চায়।

Switch-এর শেখার প্রক্রিয়া

শুরু — খালি table

       ┌──────────────────┐
       │     SWITCH       │   MAC Table:
       │  1    2    3     │   (খালি)
       └──┬────┬────┬─────┘
          │    │    │
        PC1  PC2  PC3
       AA:AA BB:BB CC:CC

Switch এখনো কিছুই জানে না। কেউ তাকে কিছু বলেনি।

ধাপ ১ — PC1 একটি frame পাঠায়

Frame: [dst: BB:BB | src: AA:AA | data]
       PC1 ──▶ port 1

Frame switch-এর port 1-এ এসে পৌঁছাল।

ধাপ ২ — Learning: source থেকে শেখা

MAC Table:
┌───────────┬──────┐
│ AA:AA:... │  1   │  ← নতুন! source MAC দেখে শিখল
└───────────┴──────┘

Switch দেখল frame-এর source AA:AA এবং সেটি এসেছে port 1 দিয়ে। সুতরাং AA:AA অবশ্যই port 1-এ। লিখে রাখল।

ধাপ ৩ — Flooding: destination অজানা

BB:BB table-এ নেই → সব port-এ পাঠাও (port 1 ছাড়া)

       ┌──────────────────┐
       │     SWITCH       │
       │  1    2    3     │
       └──┬────┬────┬─────┘
          │    ▼    ▼
        PC1  PC2  PC3
             ✓    ✓ (পেল, কিন্তু dst MAC মেলে না → ফেলে দিল)

PC3 frame-টি পেল কিন্তু destination MAC তার নয়, তাই তার NIC নীরবে ফেলে দিল — CPU পর্যন্তও গেল না।

ধাপ ৪ — PC2 উত্তর দেয়, এবং switch পূর্ণ জ্ঞান পায়

Frame: [dst: AA:AA | src: BB:BB | reply]
       PC2 ──▶ port 2

MAC Table:
┌───────────┬──────┐
│ AA:AA:... │  1   │
│ BB:BB:... │  2   │  ← এবার BB:BB শিখল
└───────────┴──────┘

এখন AA:AA জানা আছে → শুধু port 1-এ পাঠাল। Flooding নেই।

এরপর থেকে PC1 ↔ PC2 এর সব traffic শুধু port 1 ও 2 দেখবে।
PC3 আর কিছুই দেখবে না।
ℹ️ Flooding মাত্র একবার

লক্ষ্য করুন — flooding শুধু প্রথম frame-এর জন্য হলো। উত্তর আসামাত্র switch শিখে গেল। একটি চালু network-এ ৯৯% traffic-ই সরাসরি forward হয়। Flooding ব্যতিক্রম, নিয়ম নয়।

7.5 Broadcast Domain এবং Collision Domain

ধারণাসংজ্ঞাHubSwitchRouter
Collision domainযেখানে দুটি frame একসাথে পাঠালে সংঘর্ষ হয়সব port মিলে ১টিপ্রতি port-এ আলাদাপ্রতি port-এ আলাদা
Broadcast domainযেখানে একটি broadcast frame সবার কাছে যায়সব port মিলে ১টিসব port মিলে ১টিপ্রতি interface-এ আলাদা
🧠 মূল কথা এক বাক্যে

Switch collision domain ভাঙে, কিন্তু broadcast domain ভাঙে না। Router broadcast domain ভাঙে। এজন্যই ২০টি switch দিয়ে ৫০০টি machine একসাথে জুড়লে সবাই সবার broadcast পায় — সমাধান নয়। সমাধান হলো router/VLAN দিয়ে আলাদা subnet করা।

7.6 Switch এবং নিরাপত্তা — একটি সংক্ষিপ্ত সতর্কতা

Switch traffic আলাদা করে রাখে, কিন্তু এটি একটি দক্ষতার ব্যবস্থা, নিরাপত্তার নয়। MAC table-এর আকার সীমিত (কয়েক হাজার entry)। কেউ যদি হাজার হাজার ভুয়া MAC-এর frame পাঠায়, table উপচে পড়ে এবং switch বাধ্য হয়ে সব কিছু flood করতে শুরু করে — কার্যত hub-এ পরিণত হয়। একে বলে MAC flooding।

✓ এখান থেকে যা শেখার

Local network-এ traffic "কেউ দেখতে পাচ্ছে না" ধরে নেওয়া ভুল। এটিই আরেকটি কারণ কেন internal service-এও TLS ব্যবহার করা উচিত (Ch 31)। "এটা তো আমাদের private network" — এই যুক্তিতে encryption বাদ দেওয়া আধুনিক নিরাপত্তা-চিন্তায় গ্রহণযোগ্য নয় (zero-trust নীতি)।

7.7 Common Confusions

MYTH

Switch-এর IP address থাকে এবং সে IP দেখে কাজ করে।

REALITY

একটি সাধারণ (unmanaged) switch সম্পূর্ণ IP-অজ্ঞ — সে শুধু MAC দেখে। Managed switch-এ একটি IP থাকে বটে, কিন্তু সেটি শুধু তাকে configure করার জন্য (SSH/web UI), forwarding-এর জন্য নয়। Frame forward করার সময় সে IP header ছুঁয়েও দেখে না। (ব্যতিক্রম: "Layer 3 switch" নামে যেসব যন্ত্র, সেগুলো আসলে দ্রুতগতির router।)

MYTH

Switch-কে বলে দিতে হয় কোন machine কোন port-এ আছে।

REALITY

কখনোই না। Switch শুধু frame-এর source MAC দেখে নিজে নিজে শেখে। আপনি একটি নতুন switch বাক্স থেকে বের করে সব তার লাগিয়ে দিলেই কাজ শুরু করে — কারণ প্রথম কয়েকটি frame-এর মধ্যেই সে পুরো network-এর ছবি পেয়ে যায়।

🧪 Lab 7 — Local network-এ কে কে আছে

আমরা কী দেখতে চাইছি? — আপনার machine ঠিক কোন কোন local device-এর MAC জানে, এবং সেই জ্ঞান কীভাবে তৈরি হলো।

bash
# বর্তমান neighbor (ARP) table দেখুন
ip neigh                        # Linux
arp -a                          # macOS

# এখন local network-এর কয়েকটি address-এ ping দিন
for i in 1 2 3 4 5; do ping -c1 -W1 192.168.1.$i > /dev/null 2>&1 & done; wait

# আবার দেখুন — নতুন entry এসেছে
ip neigh

যা লক্ষ্য করবেন: ping দেওয়ার পর যেসব address সাড়া দিয়েছে, তাদের MAC আপনার table-এ যুক্ত হয়েছে (REACHABLE অবস্থায়)। যারা সাড়া দেয়নি তারা FAILED বা INCOMPLETE দেখাবে। কিছুক্ষণ পরে entry গুলো STALE হয়ে যাবে — ঠিক switch-এর aging-এর মতোই আপনার machine-ও পুরনো তথ্য চিরকাল রাখে না।

আমরা কী শিখলাম: Switch যেভাবে MAC table বানায়, আপনার machine-ও ঠিক সেভাবে ARP table বানায় — traffic দেখে, চাহিদা অনুযায়ী, এবং সময়ের সাথে ভুলে গিয়ে। এই "প্রয়োজনমতো শেখো, পুরনোটা ভুলে যাও" নকশাটি networking-এ বারবার ফিরে আসে (DNS cache, routing table, TCP state)।

📌 Chapter Summary
  • Switch তিনটি কাজ করে: Learn (source MAC থেকে), Forward (জানা destination-এ), Flood (অজানা বা broadcast হলে)।
  • MAC address table স্বয়ংক্রিয়ভাবে তৈরি হয় — কোনো configuration লাগে না।
  • Entry গুলো aging timer-এ (~৩০০ সেকেন্ড) মুছে যায়, যাতে device অন্য port-এ সরালেও কাজ করে।
  • Switch collision domain ভাঙে কিন্তু broadcast domain ভাঙে না; router broadcast domain ভাঙে।
  • Switch IP জানে না — সে সম্পূর্ণভাবে Layer 2-র যন্ত্র।
  • Switch দক্ষতার জন্য, নিরাপত্তার জন্য নয় — MAC flooding দিয়ে তাকে hub-এ নামিয়ে আনা যায়।
✓ Quick Check
Switch destination MAC দেখে forward করে, কিন্তু শেখে কীভাবে?

Source MAC দেখে। যখন port N-এ MAC X থেকে একটি frame আসে, switch সিদ্ধান্ত নেয় "X অবশ্যই port N-এর দিকে আছে" এবং সেটি table-এ লিখে রাখে। অর্থাৎ সে destination দিয়ে সিদ্ধান্ত নেয়, source দিয়ে শেখে।

MAC table-এ aging timer না থাকলে কী সমস্যা হতো?

একটি laptop port 3 থেকে খুলে port 7-এ লাগালে switch চিরকাল port 3-এ frame পাঠাতে থাকত — laptop কখনো traffic পেত না। Aging-এর ফলে পুরনো entry মুছে যায়, তারপর প্রথম frame flood হয়, এবং laptop উত্তর দিলেই switch নতুন port শিখে নেয়। Aging হলো ভুল তথ্য থেকে স্বয়ংক্রিয় পুনরুদ্ধারের ব্যবস্থা।

PC1 → PC2-তে পাঠানোর সময় PC3 কি কিছু পায়?

শুধুমাত্র প্রথম frame-টি, যদি switch তখনো PC2-এর MAC না জেনে থাকে (flooding)। তখনো PC3-এর NIC destination MAC মেলে না দেখে frame-টি hardware-এ ফেলে দেয় — OS পর্যন্ত পৌঁছায় না। PC2 উত্তর দেওয়ার পর switch শিখে যায়, এবং PC3 আর কিছুই দেখে না।

Broadcast frame কি switch-এর learning-কে প্রভাবিত করে?

হ্যাঁ — কিন্তু শুধু source-এর দিক থেকে। একটি broadcast frame-এর destination (FF:FF:...) কখনো table-এ যায় না (সেটি কোনো নির্দিষ্ট port নয়), কিন্তু তার source MAC ঠিকই শেখা হয়। এজন্যই ARP request (যা broadcast) switch-কে requester-এর অবস্থান শিখিয়ে দেয় — এবং সেজন্যই ARP reply-টি আর flood করতে হয় না।
