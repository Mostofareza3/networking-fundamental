Chapter 2

Network Components

Router আর switch আলাদা যন্ত্র কেন? আপনার বাসার "router" বাক্সটি আসলে কয়টি যন্ত্রের কাজ একসাথে করছে? প্রতিটি component-এর একটি নির্দিষ্ট দায়িত্ব আছে — সেই দায়িত্বগুলো আলাদা করে বুঝলে বাকি সব সহজ হয়ে যায়।

2.1 Why does this exist?

দুটি computer সরাসরি একটি তার দিয়ে জোড়া যায়। কিন্তু তিনটি? প্রতিটি জোড়ার জন্য আলাদা তার লাগলে n সংখ্যক machine-এর জন্য লাগবে n(n−1)/2 টি তার। ১০০টি machine মানে ৪,৯৫০টি তার। ১ কোটি machine-এর জন্য এই সংখ্যা কল্পনাতীত।

সমাধান হলো intermediate device — এমন যন্ত্র যাদের একমাত্র কাজ data-কে সঠিক দিকে পাঠিয়ে দেওয়া। প্রতিটি device তার নিজের সমস্যা সমাধানের জন্য জন্মেছে, এবং প্রতিটি network stack-এর নির্দিষ্ট একটি layer-এ কাজ করে (layer নিয়ে বিস্তারিত পরের chapter-এ)।

2.2 Host, Client, Server

একটি host (হোস্ট) হলো network-এ যুক্ত এমন যেকোনো device যার নিজস্ব IP address আছে এবং যে data-এর উৎস বা গন্তব্য হতে পারে। আপনার laptop একটি host, একটি data center-এর server একটি host, আপনার ফোনও একটি host।

Client এবং server hardware-এর ধরন নয় — এগুলো ভূমিকা (role):

  • Client — যে request পাঠিয়ে কথোপকথন শুরু করে
  • Server — যে অপেক্ষায় থাকে (listen করে) এবং request-এর উত্তর দেয়
ℹ️ Role, না Hardware

আপনার laptop যখন npm install চালায়, তখন সে client। সেই একই laptop-এ যখন npm run dev চালিয়ে port 3000-এ কিছু listen করছেন, তখন সে server। একই machine একই সময়ে দুটোই হতে পারে। Chapter 16-এ দেখব — পার্থক্যটা আসলে খুবই concrete: server listen() call করে, client connect() call করে।

2.3 NIC — Network Interface Card

NIC (Network Interface Card, নেটওয়ার্ক ইন্টারফেস কার্ড) হলো সেই hardware যা আপনার computer-কে network medium-এর সাথে যুক্ত করে। এর দায়িত্ব দুই দিকেই:

পাঠানোর সময়:
  Kernel থেকে পাওয়া bytes  →  বিদ্যুৎ/আলো/radio signal  →  medium

গ্রহণের সময়:
  Medium থেকে signal  →  bytes  →  kernel-কে interrupt দিয়ে জানানো

প্রতিটি NIC-এর একটি hardware-level address থাকে — MAC address (Chapter 6)। আধুনিক machine-এ সাধারণত একাধিক NIC থাকে: একটি Ethernet, একটি Wi-Fi, প্লাস কিছু virtual interface (loopback, Docker bridge, VPN)। এজন্যই ip addr চালালে একাধিক entry দেখতে পান।

⚙️ OS Connection

Operating Systems fundamentals থেকে মনে করুন — device driver। NIC-ও একটি device, এবং kernel-এ তার driver আছে। Packet এলে NIC একটি interrupt তোলে, kernel সেই interrupt handle করে packet-টিকে network stack-এ পাঠায়। খুব উচ্চ throughput-এর ক্ষেত্রে interrupt-এর সংখ্যাই bottleneck হয়ে দাঁড়ায় — তাই আধুনিক driver-রা NAPI-এর মতো polling-based কৌশল ব্যবহার করে। এটি networking এবং OS-এর সরাসরি সংযোগস্থল।

2.4 Switch — একটি local network-এর ভেতরে

একটি switch (সুইচ) একই local network-এর একাধিক device-কে যুক্ত করে এবং frame গুলোকে MAC address দেখে সঠিক port-এ পাঠায়।

            ┌─────────────┐
            │   SWITCH    │
            │ Port1 2 3 4 │
            └──┬───┬──┬─┬─┘
               │   │  │ │
             PC1 PC2 PC3 Printer

PC1 → PC2 পাঠালে switch শুধু Port 2-তে পাঠায়।
PC3 এবং Printer কিছুই দেখে না।

এটিই switch-এর মূল মূল্য। এর পূর্বসূরি hub সব port-এ সব কিছু পাঠাত — ফলে bandwidth ভাগাভাগি হতো এবং সবাই সবার data দেখতে পেত। Switch এই দুটোরই সমাধান। বিস্তারিত Chapter 7-এ।

2.5 Router — দুই network-এর মাঝে

একটি router (রাউটার) দুই বা ততোধিক আলাদা network-কে যুক্ত করে এবং packet গুলোকে IP address দেখে সঠিক পরবর্তী network-এ পাঠায়।

  Network A                       Network B
192.168.1.0/24                 10.0.0.0/24
      │                              │
      └──────┐              ┌────────┘
             ▼              ▼
          ┌──────────────────┐
          │      ROUTER      │
          │ 192.168.1.1      │  ← A-এর দিকের interface
          │ 10.0.0.1         │  ← B-এর দিকের interface
          └──────────────────┘
🧠 Mental Model — Switch vs Router

এটাই সম্ভবত networking-এর সবচেয়ে গুরুত্বপূর্ণ পার্থক্য, তাই একটি উপমা:

  • Switch = একটি ভবনের ভেতরের ডাকপিয়ন। "ফ্ল্যাট 4B" শুনলেই সে জানে কোথায় দিতে হবে। ভবনের বাইরের কিছু সে চেনে না।
  • Router = শহরের ডাকঘর। "ঢাকা 1215" দেখে সে জানে কোন শহরের দিকে পাঠাতে হবে। ভেতরের ফ্ল্যাট নম্বর নিয়ে সে মাথা ঘামায় না — সেটা গন্তব্য শহরের ডাকঘরের কাজ।

Switch local ঠিকানা (MAC) দেখে, router global ঠিকানা (IP) দেখে। এই এক বাক্য মনে রাখলে Chapter 13-এর packet journey অনেক সহজ লাগবে।

2.6 Default Gateway

Default gateway (ডিফল্ট গেটওয়ে) হলো আপনার local network-এর সেই router-এর IP address, যার কাছে আপনার machine সব "বাইরের" traffic পাঠায়।

আপনার machine-এর যুক্তি খুবই সরল, এবং প্রতিটি packet-এর জন্য এটি চালানো হয়:

destination IP আমার নিজের subnet-এর ভেতরে?
    │
    ├── হ্যাঁ  →  সরাসরি পাঠাও (ARP করে MAC বের করে)
    │
    └── না    →  default gateway-কে পাঠাও, সে বুঝবে

এটি Chapter 11-এর মূল বিষয়। এখানে শুধু এটুকু মনে রাখুন — gateway কোনো আলাদা ধরনের যন্ত্র নয়, এটি একটি ভূমিকা। যে router আপনার network-কে বাইরের সাথে যুক্ত করছে, তার local IP-ই আপনার gateway।

⚠️ আপনার বাসার "router" আসলে চারটি যন্ত্র

ঘরে যে বাক্সটিকে আমরা "router" বলি, সেটি সাধারণত একসাথে করছে: (১) modem — ISP-এর সাথে সংযোগ, (২) router — বাসার network আর Internet-এর মাঝে, (৩) switch — পেছনের ৪টি Ethernet port, (৪) access point — Wi-Fi, এবং প্রায়শই (৫) NAT + firewall + DHCP server। এই বইয়ে যখন "router" বলা হবে, তখন শুধু ২ নম্বর কাজটি বোঝানো হবে। এই একীভূত বাক্সটিই বহু বিভ্রান্তির উৎস।

2.9 Common Confusions

MYTH

Switch আর router মূলত একই জিনিস, শুধু router-এ Wi-Fi আছে।

REALITY

এরা সম্পূর্ণ ভিন্ন layer-এ ভিন্ন address দেখে কাজ করে। Switch MAC address দেখে এবং একটি network-এর ভেতরে frame পাঠায়। Router IP address দেখে এবং ভিন্ন network-এর মধ্যে packet পাঠায়। Router প্রতিটি hop-এ frame-এর MAC নতুন করে লেখে, TTL কমায় — switch এর কিছুই করে না।

MYTH

Client দুর্বল machine, server শক্তিশালী machine।

REALITY

Client এবং server হলো একটি নির্দিষ্ট কথোপকথনে নেওয়া ভূমিকা, hardware-এর শ্রেণি নয়। একটি Raspberry Pi server হতে পারে, আর একটি ৬৪-core workstation client হতে পারে। Technically পার্থক্যটা হলো: server listen() করে অপেক্ষায় থাকে, client connect() করে কথোপকথন শুরু করে।

🧪 Lab 2 — আপনার নিজের network-এর component খুঁজুন

আমরা কী দেখতে চাইছি? — এই chapter-এর component গুলোর মধ্যে কোনগুলো আপনার নিজের setup-এ আছে এবং তাদের address কী।

bash
# আপনার default gateway (মানে আপনার router) কোনটি?
ip route | grep default          # Linux
netstat -rn | grep default       # macOS

# আপনার NIC গুলোর তালিকা এবং তাদের MAC address
ip link                          # Linux
ifconfig | grep ether            # macOS

যা লক্ষ্য করবেন: ip route-এর output-এ পাবেন default via 192.168.0.1 dev wlan0-এর মতো একটি লাইন। এখানে 192.168.0.1 হলো আপনার বাসার সেই বাক্সটির router-অংশের IP, আর wlan0 হলো যে NIC দিয়ে আপনি তার কাছে পৌঁছাচ্ছেন। ip link-এ প্রতিটি interface-এর পাশে link/ether-এর পরে যে ছয়টি hex জোড়া, সেটিই MAC address।

আমরা কী শিখলাম: Gateway কোনো বিমূর্ত ধারণা নয় — এটি আপনার ঘরে রাখা একটি নির্দিষ্ট যন্ত্রের একটি নির্দিষ্ট IP address। আর আপনার machine-এর একাধিক interface আছে, প্রতিটির নিজস্ব MAC — অর্থাৎ MAC address machine-এর নয়, interface-এর।

📌 Chapter Summary
  • Host = IP address আছে এমন যেকোনো device। Client/server হলো ভূমিকা, hardware-এর ধরন নয়।
  • NIC হলো hardware যা bytes ↔ signal রূপান্তর করে; প্রতিটি NIC-এর নিজস্ব MAC address।
  • Switch = MAC দেখে, একটি network-এর ভেতরে (Layer 2)।
  • Router = IP দেখে, network-এর মাঝে (Layer 3)।
  • Default gateway হলো সেই router-এর IP যাকে আপনি সব বাইরের traffic দেন।
  • বাসার "router" বাক্সটি একই সাথে modem + router + switch + AP + NAT + firewall + DHCP।
✓ Quick Check
Switch এবং router কোন address দেখে সিদ্ধান্ত নেয়, এবং কেন সেই পার্থক্য?

Switch দেখে MAC address, কারণ তার কাজ একটি local network-এর ভেতরে frame পৌঁছে দেওয়া — সেখানে সবাই একই "ভবনে"। Router দেখে IP address, কারণ তার কাজ কোন network-এর দিকে packet পাঠাতে হবে তা ঠিক করা। MAC address-এ কোনো network-এর তথ্য নেই (এটি সমতল/flat), IP address-এ আছে (network portion + host portion) — তাই বিশ্বব্যাপী routing শুধু IP দিয়েই সম্ভব।

একটি machine একই সাথে client এবং server হতে পারে কি?

হ্যাঁ, এবং এটি খুবই সাধারণ। আপনার dev machine port 3000-এ listen করছে (server) আর একই সাথে database-এ connect করছে (client)। এমনকি একটি reverse proxy তার upstream-এর কাছে client এবং browser-এর কাছে server — একই সময়ে, একই process-এ।

আপনার বাসার একটি বাক্স আসলে কয়টি ভিন্ন কাজ করছে?

অন্তত ছয়টি: modem (ISP-এর signal রূপান্তর), router (network-এর মাঝে forwarding), switch (Ethernet port গুলোর মধ্যে), access point (Wi-Fi), NAT (private ↔ public IP অনুবাদ), এবং সাধারণত DHCP server (device-দের IP বিতরণ) ও একটি basic firewall।

MAC address কি একটি computer-এর সাথে যুক্ত, নাকি অন্য কিছুর সাথে?

MAC address যুক্ত network interface-এর সাথে, computer-এর সাথে নয়। একটি laptop-এ Ethernet ও Wi-Fi আলাদা NIC মানে আলাদা MAC। Virtual interface (Docker bridge, VPN, VM) গুলোরও নিজস্ব MAC থাকে। তাই একটি machine-এ পাঁচ-দশটি MAC address থাকা স্বাভাবিক।
