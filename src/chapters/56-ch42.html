Chapter 42

What Is the Internet?

"Internet" শব্দটির উৎপত্তি inter-network থেকে — network-দের মধ্যেকার network। এই নামটিই এর মূল প্রকৃতি বলে দেয়, এবং সেটি বোঝা জরুরি।

42.1 Internet একটি জোট, একটি network নয়

  চুক্তিভিত্তিক ব্যবস্থা, একটি প্রতিষ্ঠান নয়।

42.2 Autonomous System (AS)

একটি Autonomous System হলো একটি একক প্রশাসনিক নিয়ন্ত্রণে থাকা IP prefix-এর সমষ্টি, যার একটি নিজস্ব routing নীতি আছে।

প্রতিটি AS-এর একটি নম্বর (ASN):

  AS15169  →  Google
  AS32934  →  Meta / Facebook
  AS16509  →  Amazon AWS
  AS13335  →  Cloudflare
  AS7713   →  Telkom Indonesia
  AS17494  →  BTCL (Bangladesh)

একটি AS-এর তিনটি জিনিস থাকে:
  1. এক বা একাধিক IP prefix (যেমন 8.8.8.0/24)
  2. একটি ASN
  3. একটি routing নীতি ("কার traffic আমি বহন করব")

কারা AS হয়:
  • ISP
  • বড় প্রতিষ্ঠান (Google, Meta, ব্যাংক)
  • Cloud provider
  • বিশ্ববিদ্যালয়, গবেষণা network
  • Internet exchange

42.3 BGP — যে protocol Internet-কে জোড়া রাখে

BGP (Border Gateway Protocol) দিয়ে AS-রা একে অপরকে
বলে "আমার মাধ্যমে কোন prefix গুলোতে পৌঁছানো যায়":

  AS100 ঘোষণা করে:
    "203.0.113.0/24 → আমার কাছে আসো"
    "AS path: 100"

  AS200 সেটি শুনে নিজের প্রতিবেশীদের বলে:
    "203.0.113.0/24 → আমার মাধ্যমে যাওয়া যায়"
    "AS path: 200 100"     ← নিজের ASN যোগ করল

  AS300 শুনে বলে:
    "AS path: 300 200 100"

★ AS path দুটি কাজ করে:
  1. দূরত্বের ইঙ্গিত (কম hop = সাধারণত ভালো)
  2. ★ Loop prevention ★ — নিজের ASN path-এ দেখলে
     সেই route বাতিল করে (Ch 13-এর TTL-এর মতো ধারণা)
ℹ️ BGP পথ নয়, নীতি বাছে

একটি সাধারণ ভুল ধারণা: BGP "সবচেয়ে দ্রুত পথ" বেছে নেয়। বাস্তবে BGP-র সিদ্ধান্ত মূলত ব্যবসায়িক ও নীতিগত, কারিগরি নয়। সে latency মাপে না, bandwidth জানে না।

BGP-র অগ্রাধিকার ক্রম (সরলীকৃত): local preference (নীতি) → সবচেয়ে ছোট AS path → origin type → MED → eBGP over iBGP → নিকটতম IGP প্রতিবেশী।

লক্ষ্য করুন — local preference সবার আগে, এবং সেটি সম্পূর্ণভাবে প্রশাসকের নির্ধারিত। একটি ISP ইচ্ছাকৃতভাবে একটি ধীর কিন্তু সস্তা পথ বেছে নিতে পারে। এজন্যই কখনো কখনো ঢাকা থেকে ঢাকার একটি server-এ traffic সিঙ্গাপুর ঘুরে আসে।

42.4 Transit, Peering, IXP

TRANSIT — "আমি টাকা দিচ্ছি, তুমি আমার সব traffic নাও"

     Tier 1 ISP
         │  $$$
         ▼
     Regional ISP
         │  $$
         ▼
     Local ISP
         │  $
         ▼
      আপনি

  গ্রাহক অর্থ দেয়, provider পুরো Internet-এ
  পৌঁছানোর দায়িত্ব নেয়।


PEERING — "আমরা সরাসরি traffic বিনিময় করব, বিনামূল্যে"

     ISP-A  ◀────────▶  ISP-B
              settlement-free

  দুই পক্ষেরই লাভ:
    • Transit-এর খরচ বাঁচে
    • Latency কমে (কম hop)
    • ★ কিন্তু শুধু নিজেদের গ্রাহকদের traffic ★
      (A, B-র মাধ্যমে C-তে যেতে পারবে না)


IXP (Internet Exchange Point) — এক জায়গায় সবাই

     ┌─────────────────────────────────┐
     │        IXP (একটি বড় switch)     │
     └──┬────┬────┬────┬────┬────┬─────┘
        │    │    │    │    │    │
      ISP-A B    C  Google CDN  ...

  একটি physical port দিয়ে ডজনখানেক network-এর
  সাথে peering। খরচ ও latency দুটোই নাটকীয়ভাবে কমে।

  বড় IXP: AMS-IX (আমস্টারডাম), DE-CIX (ফ্রাঙ্কফুর্ট),
  Equinix। বাংলাদেশে: BDIX।
⚙️ Developer Perspective — কেন এই অর্থনীতি আপনাকে প্রভাবিত করে
  • Latency ভূগোল অনুসরণ করে না, অর্থনীতি অনুসরণ করে। ঢাকার দুটি ISP-র মধ্যে peering না থাকলে ঢাকা থেকে ঢাকার traffic সিঙ্গাপুর ঘুরে আসতে পারে — ৫ms-এর বদলে ১২০ms।
  • BDIX-এর মতো local IXP এজন্যই গুরুত্বপূর্ণ — স্থানীয় traffic স্থানীয়ভাবেই থাকে।
  • CDN-রা IXP-তে বসে থাকে এবং বড় ISP-দের সাথে সরাসরি peer করে — এজন্যই তাদের content এত দ্রুত (Ch 46)।
  • Cloud region বাছাই শুধু ভৌগোলিক দূরত্বের প্রশ্ন নয় — সংশ্লিষ্ট peering সম্পর্কও গুরুত্বপূর্ণ। প্রকৃত পরিমাপ (mtr) অনুমানের চেয়ে ভালো।

42.5 Tier-এর শ্রেণিবিন্যাস

Tierসংজ্ঞাউদাহরণ
Tier 1কারো কাছে transit কেনে না; শুধু peering দিয়েই পুরো Internet-এ পৌঁছায়Lumen, Arelion, NTT, Tata, GTT
Tier 2কিছু peering, কিছু transit কেনেঅধিকাংশ জাতীয় ISP
Tier 3শুধু transit কেনেছোট স্থানীয় ISP
ℹ️ "Default-Free Zone"

Tier 1 network-দের router-গুলোতে কোনো default route নেই (Ch 11)। তাদের কাছে পুরো global routing table আছে — বর্তমানে প্রায় ৯ লক্ষ IPv4 prefix এবং ২ লক্ষ IPv6 prefix। কোনো prefix সেখানে না থাকলে সেই গন্তব্য কার্যত Internet-এ নেই।

এটি Chapter 11-এর delegation শৃঙ্খলের শেষ প্রান্ত: আপনার laptop → বাসার router → ISP → regional → Tier 1। প্রতিটি স্তর "আমি জানি না, ওকে দাও" বলতে বলতে শেষে এমন কারো কাছে পৌঁছায় যে সত্যিই সব জানে।

42.6 BGP-র ভঙ্গুরতা

⚠️ BGP বিশ্বাসের উপর দাঁড়িয়ে

BGP-তে ঐতিহাসিকভাবে কোনো প্রমাণীকরণ নেই। একটি AS যেকোনো prefix ঘোষণা করতে পারে, এবং প্রতিবেশীরা সাধারণত বিশ্বাস করে — অনেকটা ARP-এর মতো (Ch 8), কিন্তু বৈশ্বিক পরিসরে।

বাস্তব ঘটনা:

  • ২০০৮ — Pakistan Telecom YouTube-এর prefix ঘোষণা করে (দেশে ব্লক করার উদ্দেশ্যে), কিন্তু ঘোষণাটি বিশ্বব্যাপী ছড়িয়ে পড়ে। YouTube প্রায় ২ ঘণ্টা বিশ্বজুড়ে অদৃশ্য।
  • ২০২১ — Facebook একটি ভুল configuration-এ নিজেদের BGP ঘোষণা প্রত্যাহার করে ফেলে। Facebook, Instagram, WhatsApp ৬ ঘণ্টা বিশ্বব্যাপী বন্ধ। এমনকি তাদের নিজেদের অফিসের দরজার card reader-ও কাজ করেনি, কারণ সেগুলোও একই network-এর উপর নির্ভরশীল ছিল।
  • বহুবার — BGP hijacking ব্যবহার করে traffic নিজের দিকে টেনে নজরদারি বা cryptocurrency চুরির ঘটনা ঘটেছে।

প্রশমন: RPKI (Resource Public Key Infrastructure) — cryptographically যাচাই করা যায় কোন AS কোন prefix ঘোষণার অধিকার রাখে। গ্রহণ ক্রমশ বাড়ছে কিন্তু এখনো সর্বজনীন নয়।

🧪 Lab 42 — Internet-এর কাঠামো নিজে দেখুন

আমরা কী দেখতে চাইছি? — আপনার packet কোন কোন AS-এর মধ্য দিয়ে যাচ্ছে, এবং কোন প্রতিষ্ঠান কোন IP-র মালিক।

bash
# আপনার ISP-র AS নম্বর
curl -s https://ipinfo.io/org; echo

# একটি IP-র মালিক কে
whois 8.8.8.8 | grep -iE "orgname|netname|origin"
curl -s https://ipinfo.io/1.1.1.1 | head -12

# AS সহ traceroute — কোন কোন প্রতিষ্ঠান পেরোচ্ছেন
traceroute -A 8.8.8.8 2>/dev/null | head -15
# বা
mtr -z -r -c 10 8.8.8.8 2>/dev/null

# একটি AS-এর সব prefix (সংখ্যা দেখুন)
whois -h whois.radb.net -- '-i origin AS15169' 2>/dev/null | grep -c "^route:"

# আপনার নিজের public IP এবং তার AS
curl -s https://ipinfo.io/json

যা লক্ষ্য করবেন: traceroute -A-তে প্রতিটি hop-এর পাশে [AS15169]-এর মতো লেখা দেখবেন — অর্থাৎ ওই router কোন প্রতিষ্ঠানের। লক্ষ্য করুন প্রথম কয়েকটি hop আপনার ISP-র, তারপর হয়তো একটি transit provider, তারপর গন্তব্যের প্রতিষ্ঠান। কখনো কখনো দেখবেন traffic অপ্রত্যাশিত দেশ ঘুরে যাচ্ছে — সেটাই peering-এর অর্থনীতি।

আমরা কী শিখলাম: "Internet" একটি বিমূর্ততা নয় — আপনার প্রতিটি packet নির্দিষ্ট কিছু প্রতিষ্ঠানের নির্দিষ্ট যন্ত্রের মধ্য দিয়ে যাচ্ছে, এবং সেই পথটি বাণিজ্যিক চুক্তি দ্বারা নির্ধারিত।

📌 Chapter Summary
  • Internet = ~৭৫,০০০ স্বাধীন AS-এর স্বেচ্ছাসম্মত জোট; কোনো কেন্দ্রীয় কর্তৃপক্ষ নেই।
  • একটি AS = নিজস্ব routing নীতিসহ একটি প্রশাসনিক ইউনিট, যার একটি ASN আছে।
  • BGP দিয়ে AS-রা prefix-এর reachability ঘোষণা করে; AS path loop prevention-ও করে।
  • BGP নীতি বাছে, পথের গুণমান নয় — local preference সবার আগে।
  • Transit = অর্থের বিনিময়ে পুরো Internet; peering = পারস্পরিক, বিনামূল্যে, শুধু নিজেদের গ্রাহকদের জন্য।
  • IXP এক জায়গায় বহু network-এর peering সম্ভব করে — খরচ ও latency দুটোই কমায়।
  • Tier 1-দের কোনো default route নেই — তারা "default-free zone"।
  • BGP-তে প্রমাণীকরণ ছিল না; RPKI সেটি যোগ করছে, কিন্তু গ্রহণ এখনো অসম্পূর্ণ।
✓ Quick Check
ঢাকা থেকে ঢাকার একটি server-এ latency ১২০ms হতে পারে কেন?

দুটি ISP-র মধ্যে সরাসরি peering না থাকলে traffic তাদের সাধারণ upstream-এ যেতে বাধ্য — যা হয়তো সিঙ্গাপুর বা হংকং-এ। ভৌগোলিকভাবে ৫ km দূরত্ব, কিন্তু network-এর পথ ৬০০০ km। এটিই local IXP (যেমন BDIX)-এর মূল যুক্তি: স্থানীয় traffic স্থানীয়ভাবে বিনিময় করা। Internet-এ দূরত্ব ভৌগোলিক নয়, topological।

Transit এবং peering-এর মৌলিক পার্থক্য কী?

Transit একটি ক্রয়-বিক্রয় সম্পর্ক: আপনি অর্থ দেন, provider আপনার traffic পুরো Internet-এ পৌঁছে দেওয়ার দায়িত্ব নেয়। Peering একটি পারস্পরিক সম্পর্ক: দুটি network সাধারণত বিনামূল্যে traffic বিনিময় করে, কিন্তু শুধু নিজেদের গ্রাহকদের traffic — আপনি peer-এর মাধ্যমে তৃতীয় পক্ষের কাছে যেতে পারবেন না।

২০২১-এ Facebook-এর ৬ ঘণ্টার outage কীভাবে ঘটল?

একটি ভুল configuration-এর ফলে তাদের router-রা BGP-তে নিজেদের prefix-এর ঘোষণা প্রত্যাহার করে ফেলে। ফলে বিশ্বের কোনো router আর জানত না Facebook-এর IP-তে কীভাবে পৌঁছাতে হয় — তারা কার্যত Internet-এর মানচিত্র থেকে মুছে গেল। পুনরুদ্ধার কঠিন হয়ে পড়ে কারণ তাদের নিজেদের internal tool ও physical access ব্যবস্থাও একই network-এর উপর নির্ভরশীল ছিল — একটি ধ্রুপদী circular dependency।

BGP কি সবচেয়ে দ্রুত পথ বেছে নেয়?

না। BGP latency মাপে না, bandwidth জানে না, congestion দেখে না। তার সিদ্ধান্তের সবচেয়ে বড় নিয়ামক হলো local preference — যা সম্পূর্ণভাবে network প্রশাসকের নির্ধারিত এবং প্রায়ই ব্যবসায়িক (কোন পথ সস্তা)। তারপরে আসে AS path-এর দৈর্ঘ্য, যা দূরত্বের একটি মোটামুটি ইঙ্গিত মাত্র। তাই BGP-র বাছাই করা পথ প্রায়ই সবচেয়ে দ্রুত নয়।
